## 1. Executive Summary & Core Architectural Principle

### Core Principle: *"The Web is the Interface, Structure is the Foundation"*
The information architecture (IA) structures Kevin Prakash J's portfolio as an interconnected, navigable topological web. Rather than forcing every granular detail to exist as an unreadable floating node, the architecture maintains a strict distinction between **Permanent Structural Web Nodes** (primary sections) and **Contextual Relational Nodes** (skills, project case studies, and research breakdowns that bloom on interaction).

All factual content is strictly grounded in the **Portfolio Master Profile v3**.

### Architectural Model Comparison

| Evaluation Metric | Model A (Ego-Centric Hub) | Model B (Linear Chain) | Model C (Contextual Distributed Web — Recommended) |
| :--- | :--- | :--- | :--- |
| **Metaphor Alignment** | Moderate (Feels like a static chart) | Low (Feels like a standard template) | **100% (Living, organic topological web)** |
| **Exploration Freedom** | High (Must always return to center) | Low (Forces sequential scroll) | **Exceptional (Direct node-to-node jumping)** |
| **Cognitive Load** | Moderate | Very Low | **Low-to-Medium (Contextual blooming prevents clutter)** |
| **Scalability** | Poor (Radial crowding) | High (Infinite vertical scroll) | **High (Graph coordinates expand cleanly)** |
| **Mobile Suitability** | Poor (Circular clipping) | High | **High (Graph compresses to clean constellation stack)** |

### Primary Recommendation: **Model C (Contextual Distributed Web)**
- **Observation**: Real engineering and research projects do not exist in linear isolation; they are deeply cross-linked with specific technologies, internships, and research questions.
- **Principle**: The primary structural nodes form a persistent pentagonal/hexagonal web scaffold, while relational child nodes bloom contextually based on the active section.
- **Recommendation**: Adopt Model C. The user can navigate directly between any primary section nodes via tensile web filaments, while context-specific sub-graphs (e.g., Skills blooming from category nodes, or TeamFlow architecture layers) emerge upon entering their respective zones.

| Node Type | Description / Contents | Interactive Trigger | Participates in Nav? | In Persistent Web? |
| :--- | :--- | :--- | :--- | :--- |
| **1. Root / Identity Node** | Kevin Prakash J — Master brand anchor, status, tagline. | Click $\rightarrow$ Return Home | Yes (Origin) | Yes |
| **2. Section Node** | 7 Primary Portals: `HOME`, `ABOUT`, `SKILLS`, `PROJECTS`, `RESEARCH`, `EXPERIENCE`, `CONTACT`. | Click $\rightarrow$ Web-Shoot Transition | Yes (Primary) | Yes |
| **3. Category Node** | Skill domains (`AI/ML`, `Web/Software`, `CV`, `Programming`, `Tools`, `Databases`, `Testing`). | Hover/Tap $\rightarrow$ Bloom child skills | No (Local Anchor) | Contextual |

| **8. External Action Node**| Outbound destinations (`GitHub`, `LinkedIn`, `Email`, `Resume PDF`). | Click $\rightarrow$ External Tab / Download | No (Utility Action) | Contextual (HUD) |

## 5. Edge & Connection Taxonomy

Edges represent mathematical and physical relationships rendered between nodes.

| Edge Type | Semantic Meaning | Visual Treatment | Permanence | Physics / Dynamic Behavior |
| :--- | :--- | :--- | :--- | :--- |
| **`EDGE_NAV`** | Navigational passage between primary sections | 1.5px solid strand, opacity 0.35 (Cyan glow on lock-on) | Permanent | High tension ($k=400$), shoots web on click, pulls viewport |
| **`EDGE_HIERARCHY`** | Parent domain to child technology | 1.0px dashed/solid strand, opacity 0.25 | Contextual (Blooms on hover) | Radial spring expansion ($k=320, c=20$), retracts on blur |
| **`EDGE_TECH`** | Technology node to project case study | 0.75px faint cyan line, opacity 0.18 | Contextual (Active on project hover) | Magnetic pull towards related project card |
| **`EDGE_RESEARCH`** | Research topic to AI model/dataset | 0.75px amber/cyan filament, opacity 0.20 | Contextual (In Research section) | Data flow pulse (animated particle stream along line) |
| **`EDGE_PROFESSIONAL`**| Experience node to skills utilized | 1.0px clean technical line, opacity 0.22 | Contextual (In Experience section) | Linear anchor connection to React, ASP.NET, RBAC |
| **`EDGE_EXTERNAL`** | Node to external link / artifact download | 0.5px dotted vector with small 45° arrow | Contextual (HUD / Contact) | Static alignment with hover highlight |

## 10. Mobile Information Architecture (Touch & Screen Adaptation)

1. **Constellation Stack Navigation**:
   - The desktop 2D canvas web collapses into a docked, swipeable **Constellation Selector** at the bottom of the viewport.
   - Touching any section indicator fires the web-pull transition to that section.
2. **Skills Web Touch Accordion**:
   - Instead of hover expansion, skill categories display as compact pill nodes with `+` expansion toggles. Tapping expands connected child technologies with animated SVG web filaments.
3. **Linear Accessibility Fallback**:
   - All content sections are stacked in clean, semantic `<section>` landmarks, allowing natural vertical scrolling while maintaining the web-pull jumps via the floating HUD.

## 11. Accessibility & Usability Framework

- **Semantic HTML Foundation**: The site is constructed using valid `<header>`, `<main>`, `<nav>`, `<section>`, `<article>`, and `<footer>` elements.
- **Keyboard Navigation**: Pressing `Tab` cycles through section nodes and interactive cards with high-contrast focus rings (`#00D2FF`).
- **Screen Reader Announcements**: Route changes and web-pull transitions announce live region updates via `aria-live="polite"`.
- **Reduced-Motion Mode**: When `prefers-reduced-motion: reduce` is detected:
  - Web physics and camera pull transitions are disabled.
  - Section changes occur via instantaneous clean opacity fades.

## 12. Open Decisions for Phase 4 (Spider-Web Navigation System)

The following parameters are intentionally isolated for Phase 4 design:
1. **Mathematical Coordinate Mapping**: Exact $(x, y)$ coordinate distribution of primary section nodes across standard viewports (1920x1080, 1440x900, 390x844).
2. **Web Shoot Vector Physics**: Exact projectile curves, bezier tension control points, and particle density per shot.
3. **Transition Timing Curves**: Fine-tuning easing curves (`cubic-bezier(0.16, 1, 0.3, 1)`) for the viewport camera pull.
